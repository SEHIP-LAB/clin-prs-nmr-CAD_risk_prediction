# Reproducibility

## Data access

This study uses data from the UK Biobank under application number 681047. Individual-level UK Biobank data are not distributed with this repository. Researchers must obtain the appropriate approval and access to the relevant data through the UK Biobank application procedure:

https://www.ukbiobank.ac.uk/enable-your-research/register

The analysis uses seven input CSV files. Their required filenames, order and column definitions are specified in `00_shared_config.ipynb`. The files are joined by the participant identifier `Eid`. Use the authorized UK Biobank exports corresponding to these definitions and retain the expected filenames and fields.

## Analysis workflow

The notebooks are numbered according to their role in the analysis.

1. **Configuration and cohort construction:** `00_shared_config.ipynb` defines shared settings and input contracts. `01_cohort_and_nmr_derivation.ipynb` constructs the analytical cohort, creates the common data partitions and prepares the candidate metabolomic score panel.
2. **Metabolomic score derivation:** `11_nmr_score249_refit.ipynb` derives the Full249-based score. `12_nmr_score106_derivation.ipynb` derives the Raw106-based score using the shared analysis partitions.
3. **Prediction modelling:** Notebooks `02`–`05` provide the modelling and evaluation workflows used by the score derivation analyses. They cover incremental predictive value, NMR representation, survival-model comparison, calibration, decision-curve analysis and joint risk stratification.
4. **Comparative and subgroup analyses:** Notebooks `13`–`15` compare the score representations and evaluate model performance across the specified population subgroups.
5. **Metabolite and sensitivity analyses:** Notebooks `06`–`10` cover metabolite associations, missingness, coverage-based sensitivity analysis, PRS–metabolite interactions and GlycA confirmation.
6. **Figure generation:** Notebooks `16`–`18` generate the main and supplementary figure collections from the corresponding analysis results.

The analysis notebooks use shared run identifiers and environment settings. Keep these settings consistent across the derivation, modelling, comparison and figure-generation stages. The relevant configuration cells document the settings used by each workflow.

## Execution notes

Run the notebooks with `notebooks/` as the working directory and retain the repository directory structure. Several downstream analyses read result tables generated by earlier notebooks; execute the relevant upstream analyses before running their dependent notebooks.

For an interrupted analysis, restart from the appropriate downstream stage only after confirming that the required upstream results are present and that the run and cohort identifiers match. Avoid reusing an output directory for a new model fit.

The `scripts/preflight.py` utility checks the expected input files and their headers. Optional checks can be enabled for ethnicity-related variables and CUDA, as required by the selected analysis. Data completeness, model inputs and analysis outputs are handled by the corresponding notebooks.

## Software environment

The main Python dependencies are listed in `requirements.txt`. The additional dependencies used by the automated software tests are listed in `requirements-validation.txt`.

For reproducible analyses, record the Python version, package versions, operating system and relevant hardware configuration used for the computation. The `scripts/capture_environment.py` utility can be used to record the computational environment.

## Analysis outputs

Analysis outputs are generated locally from the authorized input data. Participant-level data, prediction caches, fitted model files and generated notebook outputs are not distributed in this repository. Do not upload UK Biobank participant-level data or other restricted research data to the repository.

For details of the analytical components, see the notebook index in `file_naming.md`.
